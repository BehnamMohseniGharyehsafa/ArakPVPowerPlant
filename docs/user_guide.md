# User guide

1. Start the service and open the local URL. The application downloads/validates the Arak EPW if necessary and calculates a full reference run.
2. The scenario selector runs predefined physical cases. The persistent indicator shows calculation progress. The run ID at the bottom identifies the completed dataset used by charts, equipment and exports.
3. Use **Plant configuration** to edit the integer topology, module dimensions, plant location, tilt, azimuth, pitch, thermal assumptions, operational losses or finances. Capacity and GCR are derived. Apply changes with **Run simulation**. Unsaved draft edits do not alter displayed completed-run results.
4. The field supports drag to orbit, right drag to pan, scroll to zoom, arrows to pan and plus/minus to zoom. Camera buttons reset, fit, show top/isometric/oblique views and focus a selection. Select individual modules with a click; choose strings/inverters in the equipment selectors. Inspectors show stable IDs and explicit data resolution. The 2D fallback supports the same equipment selection.
5. Select a heatmap and use the reference-year timeline. The date, month and hour controls address the same local-standard-time interval. Playback advances existing results and never runs annual physics on a camera frame.
6. **Weather & resource** shows metadata-derived station coordinates, provenance, quality flags and actual weather charts. Upload an alternative complete EPW to run the same engine. Uploaded meteorology is interpreted on the documented coherent reference calendar.
7. **Physical simulation** switches hourly/daily/monthly energy views, inspects front/rear irradiance, temperature and solar geometry, and exposes electrical compatibility checks. **Energy losses** shows the signed sequential ledger and residual.
8. **Fault laboratory** configures category, target, severity, onset, duration, repair cost and safety priority. Injecting/removing events runs the physical engine. Inverter outage affects every connected string's available AC. Use **Analyse residuals** for healthy counterfactual curves and evidence. Synthetic known events and inferred power anomalies are distinguished.
9. **Predictive maintenance** evaluates response delay, counterfactual electricity and net intervention value. The open-source solver selects binary repairs within budget and capacity, prioritising declared safety-critical items. Edit costs in the fault laboratory and resource assumptions on the maintenance page, then rerun before evaluating.
10. **Cleaning optimisation** compares no cleaning, fixed interval, threshold and a daily economic optimum. Set minimum spacing and maximum operations, calculate the schedule, inspect the calendar, then **Apply optimal dates** to create a physical scenario. Price, soiling and costs remain editable; uncertainty/sensitivity can vary those assumptions.
11. **Financial performance** provides a transparent cash-flow ledger. **Uncertainty & sensitivity** specifies uniform relative half-widths, sample count and seed; each sample reruns physics. Updating a seed requires rerunning the scenario before sampling.
12. **Scenario comparison** duplicates/saves JSON configurations and runs selected cases. It retains completed summaries and selected-day power curves in the browser session. Saved configurations persist on disk. Export comparison ZIPs for reproducibility.
13. **Results & reporting** exposes all 8760 rows with pagination, interval filtering, hourly/daily/monthly CSV, equipment CSV, event/maintenance/cleaning outputs, metadata and a complete ZIP. Module exports require one selected module and are labelled allocated. **Calculate & open full report** computes missing analyses; the report supports direct PDF download and browser printing.

Plotly charts support hover, series toggling, zoom, pan, reset and SVG download. Weather-map tiles need an internet connection; numerical data and the field do not after installation/download. All commercial/economic values are illustrative. This software does not operate or remotely isolate physical equipment.
